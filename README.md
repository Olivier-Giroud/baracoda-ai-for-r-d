# AI for R&D

Python tooling and a LaTeX paper, written for submission to [arXiv](https://arxiv.org).

## Layout

```
paper/                 LaTeX source of the paper
  main.tex             entry point (preamble, title, abstract, section includes)
  sections/            one .tex file per section
  references.bib       BibTeX bibliography
  figures/             figures included by the paper (generated by scripts/)
src/ai_for_rd/         Python package (analysis code, plotting helpers)
scripts/               entry-point scripts, e.g. make_figures.py
tests/                 pytest tests
.github/workflows/     CI: runs tests and builds the PDF on every push
```

## Setup

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

To build the paper locally you need a TeX distribution with `latexmk`
(TeX Live, MacTeX or MiKTeX). If you don't have one, push your changes: CI builds
`main.pdf` and attaches it to the workflow run as an artifact named `paper`.

## Common tasks

```bash
make figures   # regenerate paper/figures/*.pdf from Python
make paper     # figures + compile paper/main.pdf
make arxiv     # build + package paper/build/arxiv.tar.gz for arXiv upload
make test      # run the Python tests
make clean     # remove LaTeX build files
```

## Writing guidelines

- One sentence per line in `.tex` files — keeps git diffs readable.
- Cite with `\citet{key}` / `\citep{key}`; reference with `\cref{label}`.
- Figures are generated by code in `scripts/`, never edited by hand, so every
  figure can be reproduced from the data.
- Use vector PDF for plots; PNG only for photos or dense images.

## Submitting to arXiv

`make arxiv` produces `paper/build/arxiv.tar.gz` containing only what arXiv
needs: the `.tex` sources, the figures and the compiled `main.bbl` (arXiv
recommends shipping the `.bbl` rather than relying on its own BibTeX run).
Upload that archive on the arXiv submission page and check the PDF it builds.
